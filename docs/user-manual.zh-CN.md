# Syncodex 使用手册

## 1. 简介

Syncodex 是一个运行在 Windows 本机的官方 Codex 同步桥接程序。

它的作用是：

- 把官方 Codex 桌面 App 的线程、消息、任务状态和文件改动同步到浏览器或手机页面
- 允许你从 Syncodex 页面继续同一个官方线程

Syncodex 不替代官方 Codex，也不自己执行模型推理。  
官方 Codex 仍然是唯一事实源。

## 2. 适用场景

适合这些使用方式：

- 在电脑浏览器里查看官方 Codex 当前线程
- 在手机上继续一个官方线程
- 在电脑上让官方 Codex 跑任务，同时在手机上盯进度
- 在忙碌时先把手机输入排进队列

## 3. 系统要求

- Windows 10 或 Windows 11
- 同一台电脑上已安装并可正常使用官方 Codex 桌面 App
- 当前用户对 `%USERPROFILE%\.codex` 目录有读取权限

## 4. 推荐启动方式

推荐直接运行打包好的程序：

```text
dist\Syncodex.exe
```

启动后，Syncodex 会常驻在 Windows 右下角托盘区域，并自动启动本地 bridge。

默认本地地址：

```text
http://127.0.0.1:8765
```

## 5. 托盘菜单

右键托盘里的 Syncodex 图标，可以看到常用菜单：

- 打开 Syncodex
- 状态
- 启动服务
- 停止服务
- 重启服务
- 手机访问...
- 停止手机访问
- 开机自动运行
- 查看日志
- 诊断
- 退出

说明：

- `手机访问...` 用来开启手机公网访问，并弹出二维码状态页
- 如果手机访问已经开启，再点一次会打开当前状态页，不会重复创建隧道
- `开机自动运行` 会写入当前用户的 Windows 启动项

## 6. 手机访问

### 6.1 开启方式

1. 先确保官方 Codex 和 Syncodex 都在运行
2. 右键托盘图标
3. 点击 `手机访问...`
4. 等待状态页打开
5. 用手机扫描二维码，或直接打开状态页里显示的公网链接

第一次使用时，Syncodex 会自动下载：

```text
dist\tools\cloudflared.exe
```

### 6.2 手机访问的特点

- 不要求手机和电脑在同一局域网
- 不需要手动开放 Windows 防火墙端口
- 本地 bridge 仍然只监听 `127.0.0.1`
- 公网访问通过临时 token 保护

### 6.3 什么时候会失效

以下情况会让手机链接失效：

- 点击“停止手机访问”
- 退出 Syncodex
- 电脑关机、休眠、断网
- 临时隧道进程退出

## 7. 基本使用流程

1. 打开官方 Codex 桌面 App
2. 打开你要继续的线程
3. 启动 `dist\Syncodex.exe`
4. 在浏览器打开 `http://127.0.0.1:8765`
5. 选择同一个线程
6. 查看消息、状态、计划、工具执行和文件改动
7. 在 Syncodex 输入框继续发消息

## 8. Syncodex 会显示什么

当前页面里你可以看到：

- 线程标题
- 当前状态
- 模型与推理档位
- 时间线消息
- 任务计划
- 文件改动摘要
- 官方队列和本地队列

## 9. 输入与发送

### 9.1 直接发送

当官方 Codex 空闲时，消息会直接发送到当前线程。

### 9.2 忙碌时发送

当官方 Codex 正在处理当前任务时：

- 手机端输入会进入 Syncodex 本地队列
- 等当前轮完成后，再按队列顺序发送

### 9.3 队列优先级

当前优先级是：

```text
官方 Codex 队列 > 自动下一步队列 > Syncodex 本地普通队列
```

### 9.4 本地队列可做什么

本地队列项支持：

- 编辑
- 删除
- 移到最前

## 10. 附件上传

目前 Syncodex 支持：

- 选择文件上传
- 粘贴剪贴板图片
- 从网页复制图片后直接粘贴

当前实现方式不是官方原生附件协议，而是：

1. 先把附件保存到运行 Syncodex 的 Windows 电脑
2. 再把本机绝对路径附带给 Codex

所以本质上是“本机文件桥接”。

## 11. 完成后动作

线程完成后，你可以在顶部 `选项` 里使用这些功能：

- 自动朗读
- 自动继续
- 自动继续最大次数
- 停止自动继续
- 生成音频

### 11.1 这些设置按线程保存

这意味着：

- 在线程 A 开启自动继续，不会自动影响线程 B
- 在线程 A 开启自动朗读，线程 B 可以继续关闭

### 11.2 自动继续

自动继续不是直接瞬时触发，而是通过 Syncodex 本地队列执行。  
这样更稳，不容易因为刷新或状态切换漏掉。

### 11.3 自动朗读

当前主路径是：

- Windows 本机生成语音 wav
- 手机端用音频播放器播放

这样比直接依赖手机浏览器 `speechSynthesis` 更稳定。

## 12. 朗读说明

### 12.1 现在怎么播

完成后自动朗读时，Syncodex 会优先朗读一段本地规则摘要，而不是把整篇回复都念完。

摘要大致会优先抓：

- 结论
- 当前结果
- 验证信息
- 下一步建议

### 12.2 音频缓存

音频缓存保留最近 1 天，之后会自动清理。

## 13. 刷新和切线程

现在切线程或刷新时，Syncodex 会尽量更快显示最近内容。  
但要注意：

- 缓存只用来加快内容显示
- 真正状态仍以后端实时同步为准

所以刷新后你可能会先看到旧消息内容，然后状态再被快速校正，这是正常行为。

## 14. 常见问题

### 14.1 页面打不开

先访问：

```text
http://127.0.0.1:8765/health
```

如果打不开，去托盘菜单点：

- 重启服务
- 查看日志
- 诊断

### 14.2 手机打不开

优先检查：

- 是否通过托盘里的 `手机访问...` 开启
- `cloudflared.exe` 是否被安全软件拦截
- 是否已经点过“停止手机访问”
- 电脑是否还在线

### 14.3 Syncodex 显示了，但官方 Codex 没收到消息

优先确认：

- 官方 Codex 桌面 App 已打开
- 目标线程在官方桌面端是可用的
- 当前发送路径没有报错

### 14.4 看到重复消息

如果偶发看到历史重复显示，先刷新当前页面再观察。  
当前系统已经做了发送去重、展示去重和跨标签页队列锁。

## 15. 高级配置

### 15.1 修改端口

```powershell
$env:SYNCODEX_PORT = "8765"
```

### 15.2 修改监听地址

```powershell
$env:SYNCODEX_HOST = "127.0.0.1"
```

### 15.3 修改发送路径

默认：

```powershell
$env:SYNCODEX_SENDER_TRANSPORT = "desktop-ipc"
```

允许安全 fallback：

```powershell
$env:SYNCODEX_SENDER_TRANSPORT = "fallback"
```

强制 legacy app-server：

```powershell
$env:SYNCODEX_SENDER_TRANSPORT = "app-server"
```

## 16. 开发模式

如果你是在本地开发或调试 Syncodex，也可以用脚本启动：

```powershell
.\scripts\start_bridge.ps1
```

停止：

```powershell
.\scripts\stop_bridge.ps1
```

构建：

```powershell
.\scripts\build_tray.ps1
```

## 17. 注意事项

- Syncodex 是非官方本地工具
- 官方 Codex 仍然是唯一事实源
- 不建议手工改官方 SQLite
- 正式运行优先使用 `dist\Syncodex.exe`
- 手机公网访问是临时方案，不是长期公开服务
